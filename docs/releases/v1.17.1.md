# v1.17.1

Patch release on the v1.17 line. Fixes authorisation and query defects found by running the package against a live
instance, and removes the two frontend entry points that had no backend behind them.

- **Requires:** Go 1.25+, `goravel/framework` v1.17.x
- **Upgrade:** `go get github.com/wcz0/goravel-admin@v1.17.1`, then re-run `go run . artisan admin:init` to backfill the
  permission/menu links (the command is idempotent, so it is safe on an existing database).

## Security

- **Anonymous access to the user list.** `config/admin.go` listed `system/admin_users` in both `auth.except` and
  `permission.except`, so `GET /admin-api/system/admin_users` returned every account without a token. Both allow-lists
  are now empty; unauthenticated requests get `401`.
- **Non-super-admins received `403` on every endpoint.** `AdminUser.AllPermissions()` tried to fill `[]AdminPermission`
  from the `AdminRoles` relation, which can never match, so it always returned nil. It now aggregates permissions
  across all roles and de-duplicates by permission id.

## Fixed

- **Permission wildcards never matched.** The pattern was stripped of its leading slash before matching, while
  `ctx.Request().Path()` is `/admin-api/...`. Matching now goes through `tools.MatchPath`, which normalises both sides.
- **Blank sidebar for regular admins.** The seeded permissions pointed at paths this package does not serve
  (`/auth/roles` and friends), and `admin_permission_menu` had no rows at all. Seeds now use the real routes and create
  the permission-to-menu links; `admin:init` backfills them.
- **Every list filter was silently ignored.** Goravel's `Where`/`WhereIn`/`Order` return a **new** `Query`; 13 call sites
  dropped the return value, so search boxes returned the full table and the `id != ?` uniqueness check never applied.
  All sites assign the result, and OR groups use `WhereAny`.
- **`admin:init` was not idempotent.** A raw `INSERT` and a `Create` each inserted the same user-role row, and the
  permission/menu/relationship steps duplicated on every run. Everything is `FirstOrCreate` now; three consecutive runs
  keep the data constant (`role_users=1 / perms=8 / menus=7 / role_perms=12 / perm_menus=18`).
- **User list had no pagination.** The response carried only `items`, so amis could not render a pager, and roles were
  queried per row. The list now returns `total` / `page` / `perPage` (capped at 500) and preloads `AdminRoles`.
- **Upgrading kept stale permission paths.** `admin:init` used `FirstOrCreate` for the eight built-in permissions, so an
  existing database kept the old `http_path` values (`/auth/roles` and friends) and non-super-admins stayed blocked.
  It now compares and updates `name` and `http_path` for those slugs when they differ. Verified by resetting one row to
  `["/auth/users"]` and re-running the command: the row came back with the real route.

## Removed

- **"Get PHP Code" button and the `/dev_tools/editor` page.** Both called `POST /dev_tools/editor_parse`, which was never
  implemented — Go has no equivalent of owl-admin's `amis()->Xxx()` codegen — so the call returned an empty `200`. The
  amis schema editor (`custom-amis-editor`) is unchanged and still edits `admin_pages` schemas.
- **The code generator leftovers.** `admin_code_generators` was a table with no model, controller or route behind it,
  plus a dead `/dev_tools/code_generator` menu entry and ~100 lines of unused copy in both language packs. The migration,
  the `admin:doctor` table check and the menu entry are gone; **the migration count drops from 13 to 12**. Existing
  databases can `DROP TABLE admin_code_generators` and delete its row from the `migrations` table.
- **`core.Menu.Extra()` and `devToolMenus()`.** Both were dead code: nothing ever called `Extra()`, and the routes it
  built pointed at frontend pages that do not exist (`user_setting`, `/dev_tools/editor`, `/dev_tools/code_generator`).
  Dev-tools pages are reached through menu records like any other admin page.
- **The "Differences from owl-admin" table in the README.** Runtime extension install, the PHP code generator and
  multi-module sub-admins are out of scope for this package rather than gaps; the README states the scope in one
  paragraph. `dev_tools/extensions` still stores the extension registry and enable/disable state.

## Verification

- `go build ./...`, `go vet ./...` and `go test ./...` pass on this branch; `example/` compiles.
- `example/smoke_admin.py` passes 20/20 contract checks against a live instance and can be re-run on the same database
  (each run uses a fresh unique suffix).
- Live checks: anonymous → `401`; a non-super-admin sees the dashboard and system menus, gets `200` on
  `system/admin_users` and `system/admin_roles`, and `403` on `system/admin_menus` and `system/permissions`.
- The embedded frontend build contains no `editor_parse` reference.

## Compatibility

- No API additions or signature changes; existing hosts only need `go get` plus `admin:init`.
- This is the Goravel 1.17 line (`goravel/framework` v1.17.3). Goravel 1.18 users should use `v1.18.1` from `main`.
