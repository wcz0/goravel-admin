# v1.18.0

First release of `goravel-admin` as an installable Goravel package on the v1.18 support line, and the first release that
reaches feature parity with owl-admin v4.7.5 on the backend contract.

- **Requires:** Go 1.25+, `goravel/framework` v1.18.x
- **Frontend:** owl-admin v4.7.5 build (amis 6.13.0) — no frontend changes needed
- **Database:** SQLite, MySQL, PostgreSQL or SQL Server

## Highlights

- **Installable package.** `go run github.com/wcz0/goravel-admin/setup install` registers the service provider and
  writes an optional `config/admin.go` skeleton. Migrations mount themselves during `Boot`; the installer no longer
  touches `bootstrap/migrations.go`.
- **Captcha on login.** `GET /captcha` issues a data-URI image and a single-use session id; enable it with
  `ADMIN_LOGIN_CAPTCHA=true`.
- **Custom amis pages.** Page schemas are stored in `admin_pages` and served through `GET /page_schema?sign=`; menus of
  type `url_type=4` render them.
- **Chunked upload.** `upload_chunk_start` / `upload_chunk` / `upload_chunk_finish` with md5 verification per part, a
  target directory allow-list and script extensions rejected.
- **xlsx export.** List pages get "export all / this page / selected" actions; downloads go through an HMAC-signed,
  expiring `_download_export` URL with path traversal protection.
- **Dev tools.** Pages, dynamic APIs (10 built-in templates), relationships (9 types with `preview_code`) and an
  extension registry, enabled with `ADMIN_SHOW_DEVELOPMENT_TOOLS=true`.
- **Icon search.** `GET /_iconify_search` serves 220k iconify names embedded in the binary.
- **Console commands.** `admin:create-user`, `admin:reset-password` and `admin:doctor`.
- **English docs.** `README.md` (English) and `README.zh-CN.md` (Chinese); this changelog is English only.

## Breaking changes

The repository is no longer a skeleton application. If you forked or copied `app/**` from an earlier commit:

- controllers, middleware, models, migrations, commands and routes now live at the package root with imports under
  `github.com/wcz0/goravel-admin/...`
- the host `main.go`, `bootstrap/` and `config/` skeletons moved to `example/`
- default configuration is provided by `config.New()` and merged into host configuration (host wins) during
  `ServiceProvider.Register`
- routes, assets and the embedded entry page are registered in `ServiceProvider.Boot`; prefixes remain `/admin`,
  `/admin-assets` and `/admin-api`
- `goravel-authz` is gone; permissions are handled by the built-in RBAC and the permission column `value` was renamed
  to `slug`

## Upgrade guide

```shell
go get github.com/wcz0/goravel-admin@v1.18.0
go run github.com/wcz0/goravel-admin/setup install
go run . artisan migrate
go run . artisan admin:doctor
```

`admin:doctor` verifies `APP_KEY`, database connectivity, the 13 core tables, admin accounts, home menu uniqueness and
broken menu parents. If you upgraded from a version that used `goravel-authz`, drop the `casbin_rules` table and the
`admin_rule` model — both are no longer used.

## Compatibility

- `admin.auth.guard` defaults to `admin` and is now used for both token issuing and middleware verification. If you
  customised `config/auth.go`, keep this key in sync.
- Goravel 1.17 users should stay on the `goravel-1.17` branch (`v1.17.x`). Goravel 1.16 is not supported: it lacks
  `foundation.Setup()`, `packages.Setup.Paths()` and `modify.RegisterProvider`.
- owl-admin capabilities with no Go equivalent (runtime extension install, PHP code generator, amis DSL editor,
  multi-module) are documented in the README under "Differences from owl-admin".

## Verification

- `go build ./...`, `go vet ./...`, `go test ./...` pass; `example/` compiles.
- `example/smoke_admin.py` passes 17/17 contract checks against a live instance: login, `_settings`, captcha, iconify
  search, page create + `page_schema` + duplicate sign, rejected ghost ids, dynamic API duplicate path, relationship
  types and preview, extension registry with `id=0` rejection, chunked upload, export download plus tampered-signature
  rejection, profile update, menus, and the schema of the four built-in list pages.
